# Link Radar for X

**X（Twitter）のリンクを、開く前に正体判定するChrome拡張。**

タイムラインやリプ欄のリンクを背景で調べて、アダルト誘導・連投スパム・有料記事・広告過多などを
判定します。危険度の高いものは**画像を色で覆って**知らせるので、うっかり開くことがありません。
引用ポストの引用元も判定します。

---

## 判定できるもの

### 画像を覆うもの（開く前に必ず気付いてほしいもの）
色はカテゴリごとに変えてあり、何で覆われているかが色でも分かります。

| バッジ | 色 | 判定方法 |
|---|---|---|
| 🔞 R18 | マゼンタ | 既知ドメイン45件 ／ URL内の明示語 ／ **RTAラベル・年齢確認ゲート**（サイト自身の申告） |
| 🚨 連投 | 深い赤 | リプ欄で**同じ登録可能ドメインが3件以上のポスト**に出現 |
| ⚠️ 要注意 | オレンジ | 既知の報告があるドメイン（既定は空。自分で追加する） |
| 🔒 有料 | 紺 | 構造シグナル（JSON-LD/meta）→ 媒体別CTA → 汎用CTA の**3層** |
| 📦 DL | 茶 | `.apk` `.exe` `.dmg` `.msi` 等への直リンク |

### 覆わないもの（小さいバッジだけ）
知っておくと良いが危険ではないので、画像は隠しません。

| バッジ | 色 | 判定方法 |
|---|---|---|
| 📊 広告多 | 青緑 | **広告"枠"の数**を数えて10個以上（社数では測れない。後述） |
| 🔑 登録 | スレート | 無料だが登録/ログインが要るウォール（有料判定が取れたら出さない） |
| 🏭 まとめ | 紫 | 既知ドメインのみ。**ヒューリスティックは使わない**（後述） |
| 📣 広告 | グレー | プレスリリース配信 ／ 広告ネットワーク経由 ／ `utm_medium=paid` 等 |
| 💰 アフィ | 黄土 | ASP約15社。Amazonは**ホスト＋`?tag=`の両方**を要求 |
| 🔗 短縮 | 青 | 既知の短縮サービス35件（`t.co` は全リンクに付くので除外） |

両方付いた場合は、覆いの中に小さいバッジを並べます（🔞R18 で覆ったうえで 🔗短縮 を小表示）。
覆いは**中身がうっすら見える濃さ**です（塗り潰すと何のリンクか分からなくなるため）。

> **判定ルールの全文**（正規表現・ドメイン全リスト・実測値・採用してはいけない語）は
> **[docs/DETECTION.md](docs/DETECTION.md)** にまとめてあります。
> このREADMEには各カテゴリの判定根拠を要約して載せています。

## インストール

Chrome ウェブストアには未公開です。手動で読み込んでください。

1. このリポジトリをダウンロード（またはclone）
2. Chromeで `chrome://extensions` を開く
3. 右上「デベロッパーモード」をON
4. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダを選択
5. x.com を開いてスクロール

> 更新したときは `chrome://extensions` で🔄を押し、**Xのタブも再読み込み**してください
> （content scriptが古いままだと反映されません）。

インストール直後から全機能が有効です。設定は不要ですが、拡張機能アイコンから
カテゴリごとのON/OFF・見せ方の変更・動作テストができます。

### 権限について
`<all_urls>`（すべてのサイトの読み取り）を要求します。**Xに表示されたリンクの中身を
背景で取得して判定するため**です。有料記事の判定・広告枠の計測・登録ウォールの検出・
短縮URLの行き先の解決は、いずれもリンク先のHTMLを見ないとできません。

- 取得するのは**画面に出たリンク先だけ**です。閲覧履歴や他のタブには一切アクセスしません。
- 取得はCookieを送らない匿名リクエスト（`credentials: "omit"`）です。
- **外部サーバーへは何も送信しません。** 判定は全てブラウザ内で完結します。
- 結果は6時間だけローカルにキャッシュします。
- 気になる場合は、ポップアップの「リンク先を取得して判定する」をOFFにできます
  （その場合 有料 / 広告過多 / 登録必須 / 短縮の行き先 は判定できなくなります）。

詳細は [PRIVACY.md](PRIVACY.md) を参照してください。

## 設計方針

このプロジェクトの判定は、次の3原則で作っています。

**1. 断定しない。**
ラベルは事実ベースの中立表現にとどめます（「アダルト」「広告枠12個」）。
サイトの品質や善悪の判断はしません。誤ラベルは実害があるためです。

**2. 誤検出より取りこぼしを選ぶ。**
判定できないものはバッジを出しません（unknown）。「たぶん怪しい」で警告を出すと、
すぐに信用されなくなって全部無視されるようになります。

**3. 閾値は実測で決める。**
「なんとなくこのくらい」ではなく、実際のサイトを取得して数えた値から決めます。

### 実測の例: 広告量は「ネットワーク社数」では測れない
GAM/AdSenseを使うサイトは初期HTMLにローダーが1〜2本あるだけで、広告枠は実行時に生成されます。
実測でも **gigazineは広告ネットワーク2社しか出ないのに、広告枠は12個**ありました。
そのため **広告"枠"の数**を主指標にしています。

| サイト | 広告枠 | 判定 |
|---|---:|---|
| alfalfalfa | 29 | ★ 広告過多 |
| gigazine（記事） | 12 | ★ 広告過多 |
| yurukuyaru | 9 | — |
| 毎日新聞（記事） | 8 | — |
| nlab / togetter / 朝日（記事） | 6 / 4 / 2 | — |
| zenn / Yahoo!ニュース / 4gamer | 0 | — |

普通の新聞記事(8枠)を超える **10** を境界にしました。yurukuyaru(9)は取りこぼしますが、
原則2に従って誤検出しない側に倒してあります。

## しくみ

```
content.js    … 画面内に入ったポストをSWへ送る(IntersectionObserver)＋本体/引用元の分割＋描画
background.js … 判定の統合・fetchキュー(並列4)・6hキャッシュ・カテゴリ設定の適用
classifier.js … URLだけで判定（アフィ/短縮/PR/まとめ/アダルト/DL）
pagesignals.js… HTMLから判定（広告枠数/アダルト自己申告/登録ウォール）
paywall.js    … HTMLから有料判定（3層）
rules.js      … 全ルール＋カテゴリ定義の一元管理
popup.js/html … 設定UI（CATEGORIESから自動生成）＋動作テスト
```

### 有料判定の3層
上ほど信頼度が高く、未登録ドメインでも 1 と 3 だけで判定できます。

1. **構造シグナル** … `isAccessibleForFree:false` / `article:content_tier=locked` / `hasPart.cssSelector` — 媒体非依存・確定的
2. **媒体別CTA** … `PAYWALL_SITES[domain].paidRe` — 実記事で確認済みのもの
3. **汎用CTA** … `GENERIC_PAYWALL_RE` — 本文を塞ぐ固有フレーズのみ（日英）

ルール登録済みの媒体: 朝日 / 読売 / 毎日 / 産経 / 日経 / 東京新聞 / 東洋経済オンライン /
ダイヤモンド・オンライン / 現代ビジネス / JBpress
（**朝日・読売・日経・東洋経済・ダイヤモンド**は実記事で確認済み `confirmed:true`）

日本の大手紙は JSON-LD `isAccessibleForFree` をほぼ吐かないため、**有料CTA文字列の正規表現**が
主判定になります。CSSクラスはハッシュ化されるのでDOMセレクタは使えません。
「残り&lt;b&gt;N&lt;/b&gt;文字」のようにタグを跨ぐケースがあるため、生HTMLとタグ除去後テキストの
**両方**で照合します。

### 連投リンクの検出
バズ投稿のリプ欄に湧く誘導リンクの主要な手口は「同じ行き先を別々のアカウントで大量投稿する」こと。
個々のURLは無害に見えても、**同じドメインが複数のポストに出ること自体が事実として異常**なので、
文面や言語に依存せず検出できます（文言を変えてくるスパムにも効く）。

- 会話ページ(`/status/`)限定。TLで人気記事が何度も流れるのは正常なので対象外。
- カウントは**登録可能ドメイン単位**（`a1.spam.top` と `a2.spam.top` を同一視）。
  ホスト完全一致だとサブドメインを回すだけで回避されるため。
- 閾値に達すると、既に描画済みの過去のポストにも遡ってバッジを付け直します。

### アダルト
3系統のどれかが当たれば判定します。

1. **既知ドメイン**（約45件）— 確実だがリストにあるものしか当たらない。
   `dmm.co.jp/digital` のように**パス前方一致**も書けるので、同一ドメインで一般向けと
   アダルトが分かれるサイト（FANZAとDMM通販）を撃ち分けられます。
2. **URL内の明示語** — `porn` `hentai` `jav` `エロ` `無修正` など。英単語は
   **区切り文字で挟まれている場合のみ**マッチさせます。そうしないと `javascript` の `jav` で誤爆します。
   さらに `SAFE_HOSTS`（大手ドメイン）では評価しません。
3. **サイト自身の申告**（要fetch）— RTAラベル、`<meta name="rating" content="adult">`、
   そして**年齢確認ゲート**（「あなたは18歳以上ですか」等）。

3 が実質いちばん強く効きます。`abc-video.site` のような無害に見える名前の新規ドメインは
URLからは絶対に判定できませんが、中身を見れば年齢確認でほぼ確実に分かるためです。
「サイト自身が宣言しているもの」を読むだけなので、こちらが推測する余地がなく誤検出しません。

### まとめ/転載
**既知ドメインリストのみで、ヒューリスティックは一切使っていません。**

本文の引用比率などで推定することは技術的には可能ですが、「まとめサイト認定」は
サイトの信用に関わるため**誤ラベルの実害が大きい**と判断しました。確実に分かっている
ドメインだけを列挙し、ラベルも「まとめ/転載」という中立表現にとどめています。

### アフィリエイト
URLパターンのみ。4つの条件形式を組み合わせます。

| 形式 | 意味 | 例 |
|---|---|---|
| `hostRe` | ホスト名の正規表現 | `hb.afl.rakuten.co.jp`, `a.r10.to` |
| `param` | パラメータの存在 | Amazon の `?tag=` |
| `paramRe` | パラメータ値の正規表現 | 楽天の `scid=af_...` |
| `paramAny` | いずれかの key / key=value | `affiliate_id`, `utm_medium=affiliate` |

Amazonは `hostRe` と `param` の**両方**を要求します。`amazon.co.jp` へのリンクでも
`?tag=` が無ければアフィリンクではないので判定しません。

### 引用ポスト
本体と引用元を別々に判定し、引用元だけを覆えます。Xが引用元をどう描くかには複数パターンがあり、
単一の前提に乗ると引用元が丸ごと処理対象から落ちるため、3段構えにしています。

1. **描画先はリンクごとに決める** — `anchor.closest(カード)`。引用元のカードリンクはアンカー自身が
   そのカードの中にあるので、引用かどうかを判定しなくても正しい場所に出る。
2. **引用元の特定は2通り試す** — `div[role="link"]` で見つからなければ、属性に依存しない構造から
   割り出す:「作者表示(`User-Name`)が2つある＝引用あり」→「2つ目を含み1つ目を含まない最大のブロック」。
3. **アンカーが無い場合を補完** — 引用元コンテナ自体がリンクなので、Xは引用元本文のURLを `<a>` にせず
   素のテキストで描くことがある。その場合は引用元のテキストからURLらしいトークンを拾う。

## 開発

### テスト
```bash
npm test
```
依存ゼロ（Node標準のみ）。ユニットテスト＋background統合テストで117件。

**動作テスト（Xを開かずに確認）**
拡張機能アイコン → 一番下の「動作テスト」にURLを貼って「判定」。
Xで出るのと同じ判定結果が出ます。カテゴリ別のプリセットボタンもあります。

**表示テスト**
`test/fixture-x.html` をブラウザで開くと、XのDOM構造を再現したダミーに実際の `content.js` と
`badge.css` を読ませた結果が見られます（判定結果はスタブ）。通常ポスト / 引用元がアダルト /
引用元に `role="link"` が無い / 引用元URLが素のテキスト / 覆わないカテゴリのみ / 画像なし
などのパターンを網羅しています。

**デモ画面（スクリーンショット用）**
`docs/demo.html` は、Xのタイムラインの見た目を再現したデモです。こちらも実際の `content.js` と
`badge.css` を読み込むので、**バッジの描画は拡張機能の実物と完全に同一**です（判定結果だけスタブ）。
ライト/ダーク切り替えと、UIパネルを隠すボタンがあります。
投稿内容は先頭の `POSTS` 配列を編集すれば差し替えられます。実在サイトを名指ししないよう、
ドメインは `.example` の架空のものにしてあります。

**実URLでの判定確認（ルール調整用）**
```bash
node test/verify-url.js "https://example.com/article"
```
実URLをfetchして全カテゴリの判定結果と、有料CTA候補の語を出します。

### ストア提出用のパッケージ

```bash
npm run pack
```
`manifest.json` / `src/` / `icons/` だけを `link-radar.zip` にまとめます。
テスト・ドキュメント・デモは含みません（ストアには不要なため）。
GitHubリポジトリにはそれらも含めて全て置いています。

### ルールを足す

**新しいカテゴリ** … `rules.js` にデータ → `classifier.js`/`pagesignals.js` に検出関数 →
`CATEGORIES` に1行 → `content.js` の `BADGE` に表示定義 → `badge.css` に色。
`CATEGORIES` に足せばポップアップの設定UIにも自動で出ます。

**有料判定の精度を上げる**
1. 対象媒体の有料記事と無料記事のURLを1本ずつ用意
2. `node test/verify-url.js "<有料記事URL>"` → 出力の「有料っぽい語」を確認
3. 有料記事だけに出る固有フレーズを `PAYWALL_SITES` の該当媒体 `paidRe` に追記、`confirmed:true` に
4. `node test/verify-url.js "<無料記事URL>"` で **無料が free と出る**ことを確認

> ⚠️ ナビやフッタに常時出る語（「有料会員」「会員限定」単体）は使わないこと。
> 無料ページでも誤検出します。**本文の続きを塞ぐ固有フレーズ**だけを採用してください。

**アダルト/要注意ドメイン** … `ADULT_HOSTS` / `CAUTION_HOSTS` に追記。
同一ドメインで一般向けとアダルトが分かれるサイトは `"dmm.co.jp/digital"` のようにパス前方一致でも書けます。

### ハマりどころ（実際にバグった箇所）

**Xの表示テキストを丸ごとURLにしてはいけない。**
カードリンクのアンカーは innerText に「ホスト＋見出し＋説明」が改行で連なります:
```
gigazine.net
【朗報】新型ゲーム機が発表される
```
これを空白除去して `https://` に繋ぐと、日本語がホスト名の一部として解釈され、URLパーサが
punycodeホスト (`gigazine.xn--net-w03bf…`) を生成します。かつてこれで**ほぼ全てのカードリンクが
誤判定**されていました。`urlFromDisplayText()` は空白区切りトークンのうち
「先頭から末尾までがホスト(+パス)」のものだけを採用します。

**`t.co` を最終ホストとして返してはいけない。**
Xのリンクは全て `t.co` に包まれています。最終ホストを `t.co` のまま返すと、`t.co` は `SAFE_HOSTS`
なので**連投判定が一度も発火しません**。`background.js` は「fetchしてよい完全なURL(`realUrl`)」と
「ホスト判定に使うホスト(`realHost`)」を明確に分け、表示テキストのホスト（パスは省略されうるが
ホストは信頼できる）を後者に使います。`test/test-background.js` がこの回帰を固定しています。

## 既知の制約

- 広告過多は**初期HTMLに置かれている広告枠だけ**を数えます。完全にJSで動的生成される枠は
  数えられず、実際より少なく出ます（誤検出は起きない方向）。
- リンクを含まないポスト（画像だけで「プロフのリンクから」と誘導するタイプ）は判定できません。
- 有料判定はサーバー側HTMLに出るマーカーだけを見ます。JSでのみ有料化する媒体は取りこぼします。
- Amazonの `tag=` はリンクが省略表示されていると拾えないことがあります（`amzn.to` 短縮は検出可）。
- 連投は同一ページ内のカウントのみ。ページを離れるとリセットされます。
- Xのレイアウト変更・各媒体のHTML変更で壊れ得ます。
